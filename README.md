# 共享实验工位续订收入桥

澄湾共享实验中心 · 合同运营组。澄湾共享实验中心经营两处共享实验空间和 84 个工位。3 名合同运营专员维护账户、工位档位与订阅的生效变动，财务月结复核岗和场地负责人据此跟踪工位续订的合同月额。

导入工位订阅生效状态 CSV。订阅编号全场唯一，需提供从首次启用至报告月末的完整变更，每个订阅每天保留一条最终状态。停订记 inactive，沿用停订前档位并填写 0 分。 输出月度合同月额收入桥、账户与档位对账、期初订阅依据和逐笔生效明细，供财务批准后导出和向运营站内分发。

- 预约系统按导出日显示当前档位，财务难以恢复月首前仍有效的工位合同。
- 运营手工汇总常把同一订阅换档的全额塞进新增和流失，月结出现重复金额。
- 同一账户可以租多个工位，停订后重开或并行加租难以追到具体合同。

## 六个业务模块

1. 工位续订概况
2. 订阅生效台账
3. 月额收入桥运行
4. 账户档位对账明细
5. 合同月额复核
6. 月结报告分发

## 工作剧本

1. 2026-11-03 09:00，合同运营组完成十月结账准备，在总览核对月初 23 条活跃工位订阅。
2. 09:10，导入 chengwan-booking-subscriptions-202610.csv 的 36 条记录，包含 9 月历史和一条 11 月 1 日已排定的月额变更。
3. 09:20，将报告月设为 2026-10，运行后核对期初 4,220,000 分和期末 4,525,000 分。
4. 09:30，在生效明细追到 CW-01-01 于 10 月 1 日从基础工位换至标准工位，转列 120,000 分并记扩张 60,000 分。
5. 09:40，在账户档位汇总核对 CW-12-02 于 10 月 16 日重新启用的 240,000 分，以及 CW-03-02 于 10 月 12 日停订的 260,000 分，确认各档位对账差额为 0 分后批准。
6. 10:00，导出十月收入桥 CSV，将 4,525,000 分期末合同月额和 25 条期末活跃订阅的报告排定发送至财务与场地运营组。

## 算法与复核

以单条活跃工位订阅的人民币合同月额整数分为口径，按生效日结转期初和期末。期初加新增、扩张和重新启用，扣收缩与流失，得期末。换档转列前后较低的月额，档位汇总加转入扣转出，全场转列抵消。

同订阅同生效日重复、订阅换户、停订缺少首次启用、停订档位不符、金额或日期无效时，请修正 CSV 后重跑。报告月请填 YYYY-MM。若对账不平，运行结果不得批准分发。 复核问题为「十月或所选报告月的期末合同月额能否按订阅生效日结转，各账户档位组的换档转列和收入变动能否追到原始订阅？」。每次分析绑定数据版本和参数，原始数据按规范化内容的 SHA-256 去重。日程针对已复核的固定结果版本，每日模式按初次投递时间每 24 小时重复。停机期间错过多次时只补一份到站内收件箱，下一次回到原时间点。

| 字段 | 含义 | 类型 |
|---|---|---|
| `account_id` | 客户账户 | str |
| `subscription_id` | 工位订阅编号 | str |
| `tier` | 生效工位档位 | str |
| `effective_date` | 生效日（YYYY-MM-DD） | str |
| `status` | 生效状态（active / inactive） | str |
| `mrr_minor` | 生效后的合同月额（分） | int |

## 启动

```sh
[ -f .env ] || cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

- Web 界面 `http://127.0.0.1:18302`
- API 文档 `http://127.0.0.1:19302/docs`
- 数据库端口 `17802`

| 账号 | 演示密码 | 工作权限 |
|---|---|---|
| analyst | analyst-demo-24 | 导入 CSV、运行分析、导出工作稿 |
| reviewer | reviewer-demo-24 | 复核、设置和停止投递、导出 |
| viewer | viewer-demo-24 | 浏览结果、导出已批准的报告、查收投递 |

原生 HTML/CSS/JavaScript 前端与 Nginx、FastAPI、Python worker、PostgreSQL 16 和 Redis 组成五服务 Compose。`backend/src/services/domain.py` 存放业务算法，`domain.json` 定义字段与验收口径，`frontend/src/pages` 为业务页面。更新任一侧源文件后，用 `docker compose up -d --build` 重建对应镜像。`backend/src/constants/enums.py` 和 `frontend/src/constants/enums.js` 定义角色及运行状态。`.env` 支持前端、API、数据库端口、演示 seed 开关和 JWT 密钥。首次部署到非演示环境时更换演示身份及 JWT/数据库凭据。

`docker compose down` 停止服务并保留数据卷。现场数据和演示结果可以在各自版本中并存。
